# Переход от волн к живой угрозе — дизайн-документ

Цель: уйти от дискретных волн к постоянному давлению двух фракций,
источники которого — часть игрового мира, а не абстрактный счётчик. Игрок
по-прежнему не управляет юнитами — только строит и апгрейдит защитные
постройки (текущая модель TD), но получает RTS-ощущение через:
экспансию ради энергии, необходимость решать где обороняться, а где
атаковать источники угрозы, и задания, выполняемые под непрерывным
давлением, а не между волнами.

Это не переписывание с нуля — большая часть текущей архитектуры
(`FactionIntel`, `spawn_points_by_faction`, `GroupFormationSystem`,
конфликт фракций, патруль, отступление на лечение) остаётся как есть и
продолжает работать с врагами независимо от того, как именно они попали
на карту.

## 1. Что меняется концептуально

| Было | Станет |
|---|---|
| `WaveProtocol` — общий счётчик волн на обе фракции | Два независимых источника угрозы, каждый со своей логикой |
| Corporation спавнится из статичных точек | Корабль высаживается в телеграфируемой точке, точка каждый раз новая |
| Fauna спавнится из статичных точек | Точки — разрушаемые сущности-гнёзда, спавн идёт, пока гнездо живо |
| Ресурсы — только кредиты, без потолка построек | Кредиты (на постройку/апгрейд) + энергия (лимит одновременно активных построек) |
| Задания привязаны к номеру волны (`SurviveWavesObjective`) | Задания привязаны к времени/событиям («продержись N сек», «удержи точку», «уничтожь K гнёзд») |
| Победа = волны закончились | Победа = выполнено задание миссии (волн как условия больше нет) |

## 2. Источники угрозы вместо волн

Общий контракт (Strategy-паттерн, аналог `FACTION_OVERRIDES` в
`GroupFormationSystem`, только для генерации угрозы):

```python
class ThreatStrategy(ABC):
    """Стратегия появления новых врагов одной фракции."""

    @abstractmethod
    def update(self, delta_time: float, game_map: "Map", spawn_factory) -> None:
        """Обновляет состояние источника угрозы, при необходимости спавнит врагов."""
```

`Map` хранит `self.threat_strategies: Dict[Faction, ThreatStrategy]` и
вызывает `strategy.update(dt, self, spawn_factory)` для каждой фракции
каждый кадр — `WaveProtocol.update()` в `GameSession` заменяется на этот
вызов (либо остаётся тонким фасадом, который просто делегирует обеим
стратегиям, чтобы не трогать сигнатуру `GameSession.update`).

### 2.1 Corporation — высадка с кораблей (`ShipLandingStrategy`)

- Раз в `landing_interval` секунд (интервал сокращается со временем —
  простая эскалационная кривая, например `max(MIN_INTERVAL, BASE - elapsed * DECAY)`)
  выбирается случайная точка на границе карты (или зона рядом с базой, если
  нужно наращивать давление ближе к финалу).
- В этой точке создаётся `PendingLanding` (не враг, а маркер: позиция,
  оставшееся время до высадки `warning_time` ~3-5 сек). `Map` хранит список
  `pending_landings`, `MapRenderer` рисует над ними предупреждающий
  индикатор (мигающий круг/иконку корабля) — у игрока есть шанс среагировать
  заранее (перебросить огонь, достроить башню на подходе).
- Когда таймер истекает — маркер убирается, на его месте через
  `spawn_factory` появляется отряд (1 лидер + эскорт, как сейчас работает
  `GroupFormationSystem`, просто формирование группы можно инициировать
  сразу, а не ждать случайного шанса) и ему прокладывается путь до базы.

### 2.2 Fauna — гнёзда (`FaunaNest` + `NestSpawnStrategy`)

Новая сущность, аналог башни, но на стороне врага. Чтобы не дублировать
код здоровья/разрушения, стоит выделить общий базовый класс:

```python
class Structure(Entity, ABC):
    """Общая база для построек с здоровьем: башен игрока и гнёзд фауны."""
    def __init__(self, position, max_health):
        super().__init__(position)
        self.max_health = max_health
        self.health = max_health

    def take_damage(self, amount, damage_type=None): ...
    def is_destroyed(self) -> bool: ...
```

`DefenseModule(Structure, ABC)` и `FaunaNest(Structure)` — оба наследуют от
`Structure`. Это небольшой рефакторинг `DefenseModule`, но убирает
дублирование health/take_damage/is_destroyed, которое сейчас размазано.

`FaunaNest`:
- Ставится на карте при генерации (несколько штук в глубине территории
  Fauna, дальше от базы, чем нынешние точки спавна — гнездо должно быть
  целью для рейда, а не просто точкой у края карты).
- Пока `is_alive()` — раз в `spawn_interval` секунд рожает 1 врага рядом с
  собой (через тот же `spawn_factory`), если локальная популяция от этого
  гнезда не превышает `MAX_NEST_POPULATION` (простой счётчик живых врагов,
  у которых `origin_nest is self`).
- Разрушено игроком (или случайно — если игрок довёл там снаряд) → навсегда
  перестаёт спавнить, `Map` может визуально пометить его как "зачищено".
- `NestSpawnStrategy.update()` в этой модели — тонкий, просто вызывает
  `nest.act(dt, spawn_factory)` для каждого живого гнезда фракции Fauna;
  вся логика спавна инкапсулирована в самом `FaunaNest`.

Гнёзда можно атаковать так же, как башни атакуют враги — только наоборот:
нужно решить, могут ли *башни* игрока автонацеливаться на гнёзда (скорее
нет — гнёзда неподвижны и находятся вне зоны обороны по замыслу), или
понадобится способ "атаковать вручную" (например, специальная
постройка/юнит с ограниченным радиусом действия, которую можно временно
выдвинуть — это уже похоже на лёгкий контроль юнита, стоит обсудить
отдельно, когда дойдём до этой фазы).

## 3. Энергия как ограничитель прогрессии

Два раздельных ресурса:

- **Кредиты** (`ResourceBank`, без изменений) — разовая стоимость
  постройки/апгрейда, тратится и пополняется за убийства, как сейчас.
- **Энергия** (`EnergyGrid`, новый класс) — не расходуется, а *резервируется*:
  у каждой активной постройки есть `energy_upkeep`, у игрока — `capacity`.
  Нельзя построить/держать активной башню, если `used + upkeep > capacity`.
  `capacity` растёт только через постройку генераторов (или, как вариант
  для второй итерации — захват фиксированных энергоузлов на карте
  постройкой рядом с ними коллектора). Для MVP — просто генератор как ещё
  один тип постройки с растущей стоимостью каждого следующего экземпляра
  (чтобы нельзя было тривиально заспамить лимит).

Это и есть источник decision-making в духе RTS: расширяться, чтобы
получить больше энергии, — значит приближаться к гнёздам и попадать под
высадки, значит нужно распределять оборону, а не просто утыкать периметр.

## 4. Задания вместо волн как условие игры

`Objective(ABC)` не меняется как контракт, но появляются новые реализации,
и волны перестают быть условием победы:

- `SurviveDurationObjective(target_seconds)` — продержаться N секунд
  реального игрового времени под непрерывным давлением.
- `DestroyNestsObjective(target_count)` — уничтожить K гнёзд Fauna.
- `HoldPointObjective(position, radius, duration)` — активировать объект и
  не дать врагам находиться в радиусе дольше `duration` суммарно/подряд.

`GameStateManager.check_victory` вместо `wave_protocol.is_all_waves_complete()`
проверяет, что **все обязательные** `Objective` в `session.objectives`
выполнены (текущий список уже поддерживает несколько заданий одновременно
— `SurviveWavesObjective`/`ProtectTowersObjective` — просто меняется
источник истины для победы).

## 5. Что убираем

- `WaveProtocol`, `WaveConfig` — полностью выводятся из `GameSession`;
  либо удаляются, либо остаются нетронутым, но неиспользуемым модулем
  (решить перед реализацией — вероятно, проще удалить и почистить тесты
  `test_wave_protocol.py`/`test_random_waves.py`, чем поддерживать мёртвый код).
- `SurviveWavesObjective` — заменяется на `SurviveDurationObjective` (или
  переименовывается/переиспользуется, если сохранить обратную
  совместимость важно).
- Статичные `Map.spawn_points_by_faction` для Fauna — заменяются списком
  `FaunaNest`. Для Corporation точки спавна как таковые исчезают вовсе
  (заменяются генерацией случайных точек высадки на границе карты).

## 6. Поэтапный план реализации

Каждый этап заканчивается тестами на новую фичу и полным прогоном
`pytest tests/ -q` — как и все предыдущие фичи в проекте.

1. **Разделение источников угрозы.** Ввести `ThreatStrategy`,
   `ShipLandingStrategy`, `NestSpawnStrategy` (пока без `FaunaNest` —
   просто спавн по таймеру в случайной точке возле старых fauna spawn
   points, без разрушаемости), вывести `WaveProtocol` из
   `GameSession.update`. Цель этапа — почувствовать новый цикл появления
   врагов, не трогая экономику/задания.
2. **`FaunaNest` и `Structure`.** Рефакторинг `DefenseModule` на общий
   `Structure`, добавление `FaunaNest` с HP/разрушением/спавном,
   размещение гнёзд на карте, отрисовка в `MapRenderer`, HUD-инфо при
   выборе гнезда.
3. **Телеграфирование высадки Corporation.** `PendingLanding`, отрисовка
   предупреждения, таймер, спавн отряда по истечении.
4. **Энергия.** `EnergyGrid`, апгрейд `DefenseModule`/фабрики с
   `energy_upkeep`, генератор как новый тип постройки, проверка лимита при
   постройке и при разрушении генератора (постройки не должны "молча"
   продолжать работать сверх лимита — нужно решить: отключать
   превышающие лимит постройки, или просто блокировать новую постройку,
   если лимит уже исчерпан, оставляя существующие в покое — второе
   проще и менее фрустрирующе для игрока).
5. **Новые задания и условие победы.** `SurviveDurationObjective`,
   `DestroyNestsObjective`, `HoldPointObjective`, переключение
   `check_victory` на задания.
6. **Баланс и полировка цикла.** Прогон партий, подбор констант
   (интервалы высадки/спавна гнёзд, лимиты энергии, скорость эскалации).
7. **Графика и звук.** Только после того, как цикл 1–5 обкатан и
   ощущается правильно — иначе есть риск делать арт под механику, которая
   ещё поменяется.

## 7. Открытые вопросы (решить по ходу, не блокируют старт)

- Нужен ли игроку способ атаковать гнёзда напрямую (лёгкий юнит/дрон с
  ограниченным радиусом действия), или это остаётся зоной "мимо основной
  обороны" и разрушается только шальным уроном/особыми башнями большого
  радиуса?
- Меняется ли размер/форма карты под территориальную модель (гнёзда
  дальше от базы, чем нынешние точки спавна)?
- Нужна ли игроку постройка-разведчик, чтобы видеть гнёзда без
  приближения к ним (сейчас `FactionIntel` раскрывает только вражеские
  башни, аналог для гнёзд ещё не продуман)?
- Стоит ли сохранить `SurviveWavesObjective` как фолбэк-режим ("классика")
  наряду с новым, или полностью его вытеснить?
