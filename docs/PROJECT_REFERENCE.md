# Tower Defense — техническая справка о проекте

Проект по ООП: Tower Defense на Python 3 + pygame. По игровому полю 4000×4000
волнами движутся враги двух враждующих друг другу фракций, игрок строит
оборонительные башни, чтобы не пропустить их к базе. Ниже — подробное описание
архитектуры, ключевых классов, алгоритмов и фич.

## 1. Общая архитектура

Проект построен слоями, каждый — отдельный пакет в `src/`:

| Слой | Назначение |
|---|---|
| `core/` | Доменная модель верхнего уровня: игровая сессия, карта, навигация, камера, состояние игры, контроллеры режимов |
| `entities/` | Игровые сущности: башни, враги, снаряды — с общей абстрактной базой `Entity` |
| `systems/` | Самостоятельные игровые системы: волны, ресурсы, групповое поведение, разведка фракций, задания |
| `factories/` | Фабрики, создающие башни/врагов по строковому имени типа, параметры берут из JSON-конфигов |
| `config/` | `ConfigLoader` — чтение и кэширование `data/config/*.json` |
| `enums/` | Все перечисления проекта в одном месте |
| `localization/` | Загрузка текстовых строк интерфейса из `data/locale/*.json` |
| `ui/` | pygame-слой: окно, игровой цикл, отрисовка карты/HUD, меню, экран победы/поражения |
| `events/`, `save_load/`, `skills/` | Пустые заготовки под будущие фичи (событийная шина, сохранения, umbrella для навыков) — в проекте не используются |

Используемые принципы ООП:

- **Наследование + абстрактные классы (ABC)** — `Entity`, `DefenseModule`, `HostileEntity`, `Projectile`, `Objective`, `IGameModeController` определяют общий контракт, конкретные подклассы (`LaserTurret`, `DroneWalker`, `HitscanBeam`, `SurviveWavesObjective`, `OrbitalModeController`…) реализуют абстрактные методы.
- **Полиморфизм** — `Map.update()` работает с любым `HostileEntity` одинаково, вызывая `enemy.act()`, `enemy.is_moving()`, `enemy.avoids_danger()`, `enemy.dodges_projectiles()`; каждый подкласс может переопределить поведение.
- **Инкапсуляция** — приватные вспомогательные методы карты (`_advance_patrol`, `_advance_retreat`, `_apply_dodge`, …) скрыты за публичным `update()`.
- **Композиция** — `GameSession` не наследует `Map`/`WaveProtocol`/`ResourceBank`, а хранит их как поля и делегирует работу; `Map` хранит `GroupFormationSystem` и словарь `FactionIntel` по фракциям.
- **Фабричный метод** — `EnemyFactory`/`TowerFactory` создают объекты по строковому ключу типа, не завязывая клиентский код на конкретные классы.
- **Dataclass** — `Coordinate` и базовый `Entity` объявлены через `@dataclass` (автогенерация `__init__`, сравнения).

## 2. Игровой цикл

```
main.py
 └── GameSession()                       # пустая модель, состояние = MENU
 └── GameView(session)                   # окно pygame, рендереры
      └── GameView.run():
           while running:
               dt = clock.tick(60) / 1000
               handle_events()           # меню либо GameController.handle_input(event)
               if state != MENU:
                   controller.update(dt)   # камера, режим
                   session.update(dt)      # волны → карта → база → состояние → задания
               render()                  # карта → HUD → оверлей победы/поражения
```

При клике «Начать игру» в меню вызывается `GameSession.setup_game()` (создаёт
карту 4000×4000, базу в центре, точки спавна по фракциям, случайные волны,
задания) и создаётся `GameController`, который на данный момент оборачивает
единственный режим — `OrbitalModeController` (свободная камера + RTS-управление
башнями). Слой `GameController`/`IGameModeController` заложен с расчётом на
несколько игровых режимов (см. `GameMode` enum: `HERO`/`TOWER_DEFENSE`), но
второй режим ещё не реализован.

## 3. Слой `core/`

### `Coordinate` (`core/coordinate.py`)
`@dataclass` с полями `x`, `y`. `distance_to(other)` — евклидово расстояние.
Кастомный `__eq__` сравнивает по значениям координат.

**Важно:** `Coordinate` — изменяемый объект. Методы движения врагов мутируют
`self.position.x`/`.y` "на месте", поэтому передавать один и тот же объект
`Coordinate` в несколько мест (например, врагу и в список точек спавна) нельзя —
это создаёт эффект "общей ссылки" (aliasing), когда движение одного объекта
незаметно двигает другой. Ровно с этим был связан баг с "уезжающей" точкой
спавна (см. историю правок, п. 15).

### `Camera` (`core/camera.py`)
Свободная камера с зумом к курсору:
- `zoom_at_mouse(mx, my, factor)` — пересчитывает `self.x/self.y` так, чтобы
  мировая точка под курсором осталась под курсором после изменения зума.
- `world_to_screen` / `screen_to_world` — линейное преобразование координат с
  учётом `zoom` и смещения камеры.
- `move(dx, dy)` — двигает камеру, ограничивая её видимой областью внутри карты.
- `update(dt, keys)` — WASD/стрелки, `Shift` — ускорение (`boost_multiplier`).

### `NavigationGrid` + `Node` (`core/navigation.py`)
Сетка клеток (`cell_size=32`) для поиска пути. **Алгоритм A\*** (`find_path`):

- Открытый список — бинарная куча (`heapq`) по `f = g + h`.
- Эвристика — евклидово расстояние с весом `HEURISTIC_WEIGHT = 1.3` (немного
  агрессивнее честного A*, путь чуть менее оптимален, но ищется быстрее —
  weighted A*).
- Диагональные шаги стоят `1.414`, ортогональные — `1.0`.
- `extra_blocked` — доп. заблокированные клетки (например, сама башня).
- `extra_cost` — доп. "штраф" стоимости для клеток (мягкое избегание радиуса
  башен, см. ниже), не блокирует проход, а делает его менее выгодным.
- `MAX_EXPANSIONS = 400` — защита от зависания на очень больших/сложных картах:
  если путь не находится за разумное число раскрытых узлов, возвращается `[]`.
- Если путь с учётом `extra_cost` не найден — `Map.path_to_base` делает вторую
  попытку без штрафов, но с сохранением жёстких блокировок.

### `GameStateManager` (`core/game_state.py`)
Хранит текущее `GameState` (`MENU`/`PLAYING`/`PAUSED`/`GAME_OVER`/`VICTORY`).
`check_defeat(base_health)` — база ≤ 0. `check_victory(map, wave_protocol)` —
все волны пройдены (`wave_protocol.is_all_waves_complete()`) и на карте не
осталось врагов.

### `Map` (`core/map.py`) — ядро игровой логики
Главный "движок" одного кадра игры. Хранит башни (`modules`), врагов
(`enemies`), снаряды (`projectiles`), сетку навигации, позицию базы,
разведданные по фракциям (`faction_intel: Dict[Faction, FactionIntel]`),
точки спавна (общие и по фракциям) и систему группового поведения.

Ключевые методы (не считая алгоритмов ИИ — они разобраны в разделе 10):

- `can_place_module` / `snap_to_grid` — валидация и привязка постройки к сетке.
- `is_position_covered(pos)` — простреливается ли точка хоть одной башней.
- `path_to_base(start, faction)` — A* до базы с мягким обходом известных этой
  фракции башен (`TOWER_AVOIDANCE_COST = 25.0` за клетку в радиусе башни).
- `replan_enemy_paths(factions=None)` — пересчитывает пути живым врагам (вызывается
  при постройке новой башни и при открытии новой башни разведкой).
- `_update_group_targets` — раз в кадр назначает лидерам групп ближайшую
  известную башню в радиусе охоты (`TOWER_HUNT_RADIUS`, у Fauna шире).
- `_find_enemy_combat_target` / `_update_vision` — межфракционный бой и
  "туман войны" (тоже раздел 10).
- `update(delta_time)` — главный метод: обрабатывает всех врагов по приоритету
  поведений, двигает башни/снаряды, возвращает `(дошедшие_до_базы, убитые)`.

### `GameSession` (`core/game_session.py`)
Модель одной партии: правила, ресурсы, фабрики, состояние. Не содержит
графики. `setup_game()` создаёт `Map`, ставит базу, точки спавна по фракциям,
генерирует случайные волны (`_generate_random_waves`) и задания. `update(dt)` —
шаг симуляции: волны → карта → здоровье базы → проверка победы/поражения →
задания. `_spawn_enemy_factory(enemy_type)` — колбэк для `WaveProtocol`:
определяет фракцию врага, берёт (копию!) точки спавна этой фракции, создаёт
врага через `EnemyFactory`, прокладывает путь через `Map.path_to_base`.

### `GameController` / `IGameModeController` / `OrbitalModeController`
`GameController` — тонкая прослойка между `GameView` и активным режимом
игры (`IGameModeController` — абстракция режима: своя камера, `update`,
`handle_input`). Сейчас единственная реализация — `OrbitalModeController`:
свободная RTS-камера, выбор/постройка башен по клавишам `1`/`2`/`3`, выбор
башни/врага кликом, апгрейд (`U`), пауза (`P`), старт волны (`SPACE`),
возврат камеры к базе (`R`).

## 4. Слой `entities/`

### `Entity` (`entities/entity.py`)
Абстрактный базовый класс-`dataclass` с единственным полем `position:
Coordinate`. Определяет `get_position`/`set_position` и абстрактный
`take_damage`.

### Башни — `DefenseModule` (`entities/defense_module.py`) + `entities/turrets.py`
`DefenseModule(Entity, ABC)` — общая логика: `range_radius`, `damage`,
`attack_speed`, `cooldown_timer`, здоровье, уровень и апгрейд.

- `update(dt, enemies)` — если не перегрета/не выключена и таймер перезарядки
  истёк, ищет цель (`find_target` — ближайший враг в радиусе) и стреляет
  (`fire`, абстрактный метод — возвращает `Projectile`).
- `upgrade()` — до 3 уровней; урон ×(1 + 0.4·(lvl-1)), радиус ×(1 + 0.2·(lvl-1)),
  скорострельность ×(1 + 0.25·(lvl-1)).
- `take_damage` / `is_destroyed` — башню тоже можно разрушить (враги умеют её
  атаковать, см. раздел 10).

Три конкретные башни (параметры по умолчанию переопределяются `data/config/towers.json`):

| Класс | Урон/тип | Особенность снаряда |
|---|---|---|
| `LaserTurret` | `ENERGY`, быстрая | `HitscanBeam` — мгновенный луч, попадание гарантировано |
| `BulletTurret` | `KINETIC`, средняя | `BulletProjectile` — летит по прямой к позиции цели на момент выстрела |
| `MortarTurret` | `EXPLOSIVE`, медленная, мощная | `MortarShell` — парабола + шрапнель по кругу при падении |

### Снаряды — `Projectile` (`entities/projectile.py`)
Абстрактный `Projectile(ABC)`: `update(dt, enemies) -> bool` (жив ли ещё),
`collect_spawned()` (для мортиры — осколки).

- `HitscanBeam` — наносит урон цели мгновенно на первом кадре, дальше не
  существует (визуально это луч от башни до цели).
- `_LinearProjectile` — общий класс для летящих по прямой снарядов:
  двигается на `speed·dt`, проверяет столкновение по отрезку пути этого кадра
  (`_find_path_collision` — ищет ближайшего врага, чей центр попадает в
  `HIT_RADIUS` от отрезка), исчезает при попадании или превышении
  `max_distance`.
  - `BulletProjectile(_LinearProjectile)` — направление фиксируется в момент
    выстрела (к позиции цели тогда, не самонаводится).
  - `ShrapnelPellet(_LinearProjectile)` — осколок мортиры, разлетается от
    точки падения.
- `MortarShell` — летит по параболе (`4·PEAK_HEIGHT·t·(1-t)` для высоты,
  линейная интерполяция позиции по `t = elapsed/flight_time`), при `t≥1`
  "взрывается" — создаёт `SHRAPNEL_COUNT=8` `ShrapnelPellet` по кругу
  (`collect_spawned()` их отдаёт наружу, `Map.update()` добавляет в общий
  список снарядов).

### Враги — `HostileEntity` (`entities/hostile_entity.py`) + `entities/enemies.py`
`HostileEntity(Entity, ABC)` — общая база всех врагов: здоровье, скорость,
броня, фракция, радиус обзора, путь (`path`/`path_index`), состояние группы
(`group_id`, `is_group_leader`, `group_leader`, `formation_offset`), цель-башня
(`target_tower`), состояние патруля (`is_patrolling`, `patrol_angle`,
`patrol_direction`), состояние лечения (`is_healing`), состояние уклонения
(`dodge_timer`, `_dodge_offset`).

Ключевые методы (полиморфные хуки для `Map.update()`):

- `act(dt, in_danger)` — **абстрактный**, особое поведение конкретного типа на
  кадр (у всех текущих врагов — no-op; раньше `ScoutDrone` тут "замирал" на
  разведку, сейчас это поведение убрано в пользу `avoids_danger()`).
- `is_moving() -> bool` — может ли двигаться в этот кадр (по умолчанию `True`).
- `avoids_danger() -> bool` — должен ли **убегать** от простреливаемой зоны
  вместо боя/движения к базе (по умолчанию `False`, `True` у `ScoutDrone`).
- `dodges_projectiles() -> bool` — должен ли покачиваться из стороны в
  сторону под обстрелом (по умолчанию `self.armor == ArmorType.LIGHT`).
- `move_along_path(dt)` — движение по заранее проложенному пути (список
  `Coordinate`), возвращает, дошёл ли до конца.
- `move_towards_point(target, dt)` — прямое движение к произвольной точке, в
  обход маршрута (используется для боя, бегства, патруля, отступления,
  следования за лидером группы).
- `take_damage(amount, damage_type)` — с учётом резиста брони (раздел 11).
- `attack_tower` / `attack_enemy` — наносят фиксированный
  `ATTACK_DAMAGE_PER_SECOND·dt` урон (кинетический).
- `group_target_tower()` — если лидер — свою цель, если ведомый — цель своего
  лидера, иначе `None`.

Пять конкретных типов врагов (параметры переопределяются
`data/config/enemies.json`):

| Класс | Фракция | Броня | HP | Скорость | Особое поведение |
|---|---|---|---|---|---|
| `DroneWalker` | Corporation | Light | 60 | 50 | `dodges_projectiles()=True` (лёгкая броня) |
| `HeavyAssaultDrone` | Corporation | Heavy | 180 | 35 | тип-лидер групп Corporation |
| `ScoutDrone` | Corporation | EnergyShielded | 100 | 70, обзор 260 | `avoids_danger()=True` — только разведка и бегство, не участвует в группах (`SOLO_TYPES`) |
| `GiantRoach` | Fauna | Heavy | 250 | 25 | тип-лидер групп Fauna |
| `BioTitan` | Fauna | Organic | 400 | 20 | тип-лидер групп Fauna |

## 5. Слой `systems/`

### `GroupFormationSystem` (`systems/group_formation.py`)
Раз в кадр случайно формирует эскорт вокруг врага-лидера. Профиль поведения
зависит от фракции (`FACTION_OVERRIDES`):

- `LEADER_TYPES` — какие типы врагов **могут стать** лидером (Corporation:
  `heavy_assault_drone`; Fauna: `giant_roach`, `bio_titan`).
- `SOLO_TYPES` — какие типы **никогда** не участвуют в группе — ни лидером, ни
  ведомым (`scout_drone`; для Fauna пусто).
- `FORM_CHANCE_PER_SECOND`, `GROUP_RADIUS`, `MAX_ESCORT_SIZE`,
  `FORMATION_RADIUS` — вероятность формирования в секунду, радиус поиска
  кандидатов, макс. размер эскорта, радиус построения вокруг лидера.

Алгоритм `update()`: для каждого живого врага подходящего лидер-типа, ещё не
состоящего в чьей-то группе, с вероятностью `chance·dt` выбирается случайный
кандидат той же фракции в радиусе (исключая `SOLO_TYPES` и уже
сгруппированных), лидер помечается (`is_group_leader=True`, новый `group_id`),
кандидат становится ведомым (`join_group`) со смещением по кругу
(`formation_offset`, равномерно распределено по `2π/max_escort_size`).

### `FactionIntel` (`systems/faction_intel.py`)
"Память" одной фракции о башнях игрока — реализация тумана войны на стороне
врагов. `reveal(tower)` помечает башню известной (возвращает `True`, только
если это произошло впервые — используется как триггер для реплана путей),
`knows(tower)`, `known_towers()`.

### `WaveProtocol` + `WaveConfig` (`systems/wave_protocol.py`)
`WaveConfig(enemy_types, count, interval)` — описание одной волны: список
типов врагов (циклически чередуются при спавне), сколько всего заспавнить,
интервал между спавнами.

`WaveProtocol` — автомат состояний волны: `is_active` → спавнит по таймеру
через колбэк `spawn_factory(enemy_type) -> Optional[HostileEntity]`
(фракцию/позицию/путь определяет вызывающий код — сам протокол ничего не
знает про фракции и точки спавна, полностью развязан от `Map`); когда
заспавнено `config.count` и на карте не осталось врагов — волна завершена,
активируется `cooldown_timer` (5 сек) до следующей. `force_start_next_wave()`
— досрочный старт (кнопка `SPACE`). `is_all_waves_complete()` — все волны
пройдены.

### `ResourceBank` (`systems/resource_bank.py`)
Кредиты игрока. `spend(amount)` — списывает, если хватает. `add_reward(amount)`
— начисляет за убитого врага (`enemy.reward`).

### `Objective` / `SurviveWavesObjective` / `ProtectTowersObjective` (`systems/mission.py`)
Необязательный слой заданий поверх волнового цикла. `Objective(ABC)` —
`completed`/`failed`/`is_active()`, абстрактные `update(session)` и
`describe(session)`. `SurviveWavesObjective` — продержаться до N-й волны (N —
половина от общего числа волн, см. `GameSession.setup_game`).
`ProtectTowersObjective` — не потерять ни одной башни за игру
(`map.towers_lost_count`).

## 6. Слой `factories/` и `config/`

`EnemyFactory` и `TowerFactory` — паттерн **Фабричный метод**: `register(type_name,
class)` заносит класс в реестр, `create(type_name, position)` достаёт JSON-конфиг
через `ConfigLoader`, конвертирует строковые enum-поля (`armor`, `faction`) и
создаёт экземпляр `class(position, **config)`, проставляя `type_name` для
последующего сравнения (используется в `GroupFormationSystem`, `HUD`,
`MapRenderer`). `EnemyFactory.faction_for(type_name)` — фракция типа без
создания объекта (по умолчанию `Faction.FAUNA`, если не указана в конфиге).

`ConfigLoader` (`config/config_loader.py`) — читает и кэширует
`data/config/towers.json` / `enemies.json`. При заморозке в exe (PyInstaller)
путь берётся из `sys._MEIPASS`. Если файл отсутствует/битый — тихо
возвращает `{}` (конструктор класса подставит значения по умолчанию).

## 10. Ключевые алгоритмы и фичи ИИ

Вся логика решения "что делает враг в этом кадре" сосредоточена в
`Map.update()` и вызываемых из него приватных методах. На каждом кадре для
каждого живого врага вычисляются флаги-приоритеты, и в порядке убывания
приоритета выбирается ветка поведения:

```
1. retreating_now   — отступление на лечение (если применимо)
2. in_combat         — бой с врагом чужой фракции в радиусе обзора
3. hunting_tower      — эскорт/лидер преследует известную башню
4. in_danger and avoids_danger()  — бегство от простреливаемой зоны (разведчик)
5. (иначе) следование за лидером группы либо обычное движение к базе
   (с патрулированием периметра при необходимости)
```

Дополнительно, независимо от выбранной ветки: пассивное лечение рядом со
своим спавном и боковое покачивание (`dodge`) под обстрелом применяются как
"надстройка" поверх любого движения.

### 10.1 A* с мягким обходом башен (`path_to_base`)
Обычный A* (см. `NavigationGrid.find_path`) сам по себе просто ищет
кратчайший путь. Чтобы враги реалистично избегали (но не полностью
игнорировали при отсутствии альтернатив) известные им башни, `path_to_base`
не блокирует клетки в радиусе действия башни, а добавляет им "штраф"
(`TOWER_AVOIDANCE_COST = 25.0` за каждую перекрывающую башню) — путь через
простреливаемую зону остаётся возможным, но алгоритм предпочтёт обходной
путь, если он не сильно длиннее. Если даже со штрафами путь не найден —
повторный поиск без штрафов (только с жёсткими блокировками — сама клетка
башни).

### 10.2 Туман войны / разведка фракций (`FactionIntel`, `_update_vision`)
Каждая фракция видит башни игрока только в радиусе обзора (`vision_radius`)
своих живых юнитов. `_update_vision` раз в кадр раскрывает новые башни
(`FactionIntel.reveal`), и если для фракции появилась хотя бы одна новая
известная башня — вызывается `replan_enemy_paths` только для юнитов этой
фракции (чужая фракция не узнаёт о разведке другой).

### 10.3 Межфракционная вражда (`_find_enemy_combat_target`)
Corporation и Fauna враждебны друг другу: любой враг, увидевший в своём
`vision_radius` живого врага чужой фракции — ближайшего — вступает с ним в
бой (`attack_enemy`, если дистанция ≤ `ATTACK_RANGE`, иначе подходит
`move_towards_point`). Это высший приоритет движения — бой прерывает
патрулирование, охоту на башню, обычное движение к базе.

### 10.4 Охота на башни группой (`_update_group_targets`, `TOWER_HUNT_RADIUS`)
Лидеру группы, если у него нет живой цели, назначается ближайшая известная
башня в радиусе охоты (`TOWER_HUNT_RADIUS = 300`, у Fauna `450` — агрессивнее).
Цель хранится только у лидера; `group_target_tower()` даёт её и ведомым —
вся группа атакует одну и ту же башню.

### 10.5 Групповое поведение и следование за лидером
См. `GroupFormationSystem` (раздел 5). В `Map.update()`, если враг —
ведомый и его лидер жив и ещё не дошёл до конца пути, он двигается не по
своему маршруту, а к `leader.position + formation_offset`
(`move_towards_point`). Если лидер погиб или дошёл до базы — ведомый
покидает группу (`leave_group()`) и дальше действует самостоятельно.

### 10.6 Бегство разведчика от башен (`ScoutDrone.avoids_danger`)
`ScoutDrone` — чистый разведчик: не сражается, не участвует в группах
(`SOLO_TYPES`), никогда не становится лидером (не входит в `LEADER_TYPES`).
Как только он попадает в радиус действия хотя бы одной башни
(`is_position_covered`), вместо движения к базе он убегает от ближайшей
накрывающей башни — целевая точка вычисляется как направление "от башни",
на `range_radius + 50` от её позиции (`_flee_point_from`).

### 10.7 Патрулирование периметра базы (поиск "слабого места")
Если известная башня перекрывает **текущее направление** от врага к базе
(угол-пеленг относительно базы, `_bearing_from_base`, окно допуска
`GAP_ANGULAR_WINDOW = 25°`), враг не идёт напролом и не встаёт на месте, а
начинает кружить (`is_patrolling=True`) по окружности вокруг базы радиусом
`PATROL_RADIUS_PADDING (150) + range_radius самой дальнобойной известной
башни`, медленно вращаясь (`PATROL_ANGULAR_SPEED = 0.5 рад/с`, направление
вращения фиксируется по чётности `id(enemy)` — половина патрулирующих кружит
по часовой, половина против). Как только текущий пеленг врага совпадает со
свободным от башен направлением — патруль снимается, путь до базы
пересчитывается заново, и враг идёт обычным маршрутом. Реализация:
`_bearing_from_base`, `_is_gap_at_angle`, `_advance_patrol`, `_advance_towards_base`.

### 10.8 Уклонение от выстрелов (`dodges_projectiles`, `_apply_dodge`)
Враги с лёгкой бронёй (`ArmorType.LIGHT`, сейчас — `DroneWalker`) под огнём
любой башни (`in_danger`) вместо движения строго по прямой добавляют
боковое синусоидальное покачивание перпендикулярно направлению текущего
шага: `wiggle = DODGE_AMPLITUDE(24) · sin(dodge_timer · DODGE_FREQUENCY(5))`,
к позиции добавляется **разница** между новым и предыдущим значением
`wiggle` (не абсолютное значение) — это даёт плавное ограниченное колебание
без накопительного дрейфа в сторону.

### 10.9 Отступление на лечение (`is_healing`, retreat-to-heal)
Если здоровье врага падает ниже `WOUNDED_HEALTH_RATIO (30%)` от максимума —
он (если это одиночка или лидер группы; ведомые решение не принимают, а
просто следуют за отступающим лидером) отступает к ближайшей точке спавна
своей фракции (`_advance_retreat`) и не трогается с места, пока не долечится.
Если ранен **кто-то из группы** (не обязательно лидер) — отступает вся
группа (`_group_needs_healing` проверяет всех живых членов с тем же
`group_id`). Рядом с любой точкой спавна своей фракции (`HEAL_RADIUS = 150`)
**любой** враг пассивно регенерирует `HEAL_RATE_PER_SECOND (15% от max_health)`
в секунду — это отдельное, не завязанное на отступление правило, поэтому
ведомые лечатся "за компанию", просто оказавшись рядом с лечащимся лидером.
Отступление снимается только когда **все** члены группы долечились
(`_group_fully_healed`), после чего путь до базы прокладывается заново.
Отступление имеет наивысший приоритет среди "мирных" веток (выше бегства
разведчика), но не прерывает уже начавшийся бой или охоту на башню.

**Ограничение против затягивания волны:** если на карте осталось
`≤ LOW_ENEMY_COUNT_NO_RETREAT (4)` живых врагов — отступление отключается
(уже начавшееся — принудительно снимается), чтобы добивание последней
волны не растягивалось на лечение горстки выживших.

### 10.10 Разрушение башен (эскорт-осада)
Пока цель-башня жива и в радиусе атаки — враг (лидер или одиночка,
преследующий башню) наносит ей урон (`attack_tower`, кинетический,
`ATTACK_DAMAGE_PER_SECOND`). Разрушенные башни (`is_destroyed()`) убираются
из `Map.modules` в начале следующего кадра, `towers_lost_count` растёт (влияет
на задание `ProtectTowersObjective`).

## 11. Боевая система и урон

`DamageType` × `ArmorType` — резист 50% при совпадении "профильной" пары:

| Броня | Резист 50% против |
|---|---|
| `HEAVY` | `KINETIC` |
| `ENERGY_SHIELDED` | `ENERGY` |
| `ORGANIC` | `EXPLOSIVE` |
| `LIGHT` | — (нет резистов, но `dodges_projectiles()=True`) |

Итоговый урон: `amount · (1 - reduction)`, `reduction = 0.5` если тип брони
и тип урона образуют профильную пару, иначе `0`. Логика — в
`HostileEntity.take_damage`. Аналогичной системы резистов у башен нет —
`DefenseModule.take_damage` просто вычитает урон.

Снаряды наносят урон либо мгновенно (`HitscanBeam`), либо при попадании по
геометрии полёта (`_LinearProjectile._find_path_collision` — проверка
отрезка "предыдущая→новая позиция снаряда" против всех живых врагов в
`HIT_RADIUS`), либо взрывом с разлётом шрапнели (`MortarShell`).

## 12. Волны, ресурсы, задания, победа/поражение

- **Волны:** `GameSession._generate_random_waves()` при старте партии
  генерирует случайное число волн (4–7), в каждой — случайный набор из 1–3
  типов врагов и количество, растущее от волны к волне
  (`randint(18+i, 22+i·2)` — волны наращиваются примерно с 18–22 врагов и
  растут дальше), интервал спавна 0.7–1.5 сек.
- **Спавн:** `WaveProtocol` не знает о фракциях/точках спавна — на каждый тик
  вызывает `spawn_factory(enemy_type)`, которым выступает
  `GameSession._spawn_enemy_factory` — определяет фракцию, берёт случайную
  (скопированную!) точку спавна этой фракции, создаёт врага, прокладывает
  путь.
- **Ресурсы:** `ResourceBank` — кредиты, тратятся на постройку/апгрейд башен,
  начисляются за убийство врага (`enemy.reward`).
- **Победа/поражение:** база теряет 10 HP за каждого дошедшего врага;
  поражение при HP базы ≤ 0; победа — все волны пройдены и на карте не
  осталось живых врагов.
- **Задания** (`Objective`) — необязательный слой поверх основного цикла,
  не влияет на победу/поражение партии напрямую, только на отображаемый в
  HUD статус (пройдено/провалено).

## 13. Конфигурация и локализация (data-driven)

Параметры башен и врагов не зашиты в код — читаются из
`data/config/towers.json` / `enemies.json` через `ConfigLoader` и
подставляются в конструктор класса как `**config` (при отсутствии файла или
поля используются значения по умолчанию из сигнатуры конструктора). Это
позволяет балансировать игру без пересборки кода. Аналогично весь текст
интерфейса вынесен в `data/locale/ru.json` и читается через `Loc`/`loc.get()`
— смена языка сводится к добавлению нового файла локали.

## 15. Известные особенности и ограничения

- **Циклический импорт `src/core/__init__.py`.** Эйгерный
  `from .map import Map` + `from .game_session import GameSession` создаёт
  хрупкость при запуске отдельных тестовых файлов в изоляции (например,
  `pytest tests/test_wave_protocol.py` в одиночку может упасть с
  `ImportError`, если он первым модулем трогает `src.core`). При запуске
  **полного** набора тестов (штатный сценарий, `pytest tests/`) порядок
  импорта "прогревает" `sys.modules`, и проблема не проявляется. Осознанно не
  исправлено — потребовало бы переработки eager-экспортов пакета,
  тангенциально к решаемым задачам.
- **`src/entities/__init__.py`** не экспортирует `HeavyAssaultDrone` и
  `BioTitan` (только исходные `DroneWalker`, `GiantRoach`, `ScoutDrone`) —
  сами классы и вся логика работают, но при импорте через
  `from src.entities import HeavyAssaultDrone` придётся импортировать из
  `src.entities.enemies` напрямую.
- **`README.md` частично устарел**: перечисляет «3 типа противников
  (DroneWalker/GiantRoach/ScoutDrone)», хотя фактически их пять — добавлены
  `HeavyAssaultDrone` и `BioTitan` (правки README из этого списка выпали, так
  как фича добавлялась отдельным этапом).
- **`Coordinate` — изменяемый объект**, движение мутирует его "на месте"
  (`self.position.x += ...`). Любой код, который передаёт врагу/сущности
  разделяемый объект `Coordinate` (вместо копии), рискует получить эффект
  "aliasing" — именно так раньше "уезжала" точка спавна вслед за врагом,
  который её унаследовал по ссылке (исправлено копированием координаты в
  `GameSession._spawn_enemy_factory`).
- **`events/`, `save_load/`, `skills/`** — пустые пакеты-заготовки, не
  реализованы и нигде не импортируются.
- **Второй игровой режим (`GameMode.HERO`)** заложен в архитектуре
  (`IGameModeController`, `GameController.set_mode`), но не реализован —
  используется только `OrbitalModeController`.
